# Siege pick-crash bisection variants

`maps/builds/crossroads-siege.w3x` still crashes current Reforged the moment
it is clicked in the multiplayer map list (it survived the earlier fixes:
weather bytes, minimap, HM3W flags, MDX sanity). These six builds are the
unmodified siege source (`maps/crossroads-siege/`, untouched) with exactly
ONE suspect subsystem removed or simplified each, so a single in-game pass
tells us which file the game chokes on. All six pass `validate-map` (0
failures) and keep the HM3W header mirrored to the packed w3i.

Generated by `make-variants.js` in the session scratchpad
(`lobby-diag/make-variants.js`); rebuild by re-running that script — the
transforms are applied to a temporary copy of the source, never to
`maps/crossroads-siege/` itself.

## How to test (in order — report the FIRST one that does NOT crash)

Copy the .w3x files into your Warcraft III `Maps/` folder, then in the
multiplayer map list click each in this order. The first variant that shows
its description without crashing identifies the culprit subsystem:

| # | File | What was removed / changed | If this one stops the crash, the culprit is |
| - | ---- | -------------------------- | ------------------------------------------- |
| 1 | `siege-no-objabil.w3x` | `war3map.w3a` + `war3map.w3t` dropped (custom ability A000, items I000/I001); w3u kept, its dangling `A000` ability reference stripped; `useCustomAbilities` flag cleared | the ability/item object data files |
| 2 | `siege-no-import.w3x` | `war3mapImported/SiegeCrystal.mdx` + `war3map.imp` dropped; `n000`'s model re-pointed at built-in `units\nightelf\Wisp\Wisp.mdl` | the custom MDX import / import manifest |
| 3 | `siege-no-sounds.w3x` | `war3map.w3s` dropped | the sounds file |
| 4 | `siege-no-objdata.w3x` | ALL object data dropped (`w3u`/`w3t`/`w3a`); placed custom units swapped to their base types (h000→hfoo, h001→htow, n000→nech); `useCustomAbilities` cleared | the unit object data (w3u) — since #1 alone didn't fix it |
| 5 | `siege-2p.w3x` | players cut to 2 users, forces reshaped to the (fixed) tidewatch 1v1 shape, slocs/units of players 2-4 dropped, config() reduced to match, header maxPlayers=2 | player/force/start-location count |
| 6 | `siege-minimal-lua.w3x` | `war3map.lua` replaced by a minimal config()+main()+CreateAllUnits() script (all data files byte-identical to the baseline build) | the big map script itself |

Notes:

- Variants are cumulative in *coverage*, not in content: each removes only
  its own subsystem, everything else is identical to the baseline build.
- Variants 1, 2, 4 and 6 will play degraded (missing boss ability, placeholder
  crystal model, no custom units, or no wave logic) — that is expected; only
  the pick-time crash matters for this test.
- If ALL six still crash, the culprit is in what they share: terrain (64x64
  w3e), doodads, regions, cameras, wpm/shd/mmp, or the archive layout — say
  so and we bisect that half next.
- If several would fix it, the earliest in the list is the most specific.

Do not use these for play; the reference build stays
`maps/builds/crossroads-siege.w3x`.
